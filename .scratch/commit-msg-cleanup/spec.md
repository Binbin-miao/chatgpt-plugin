# Spec 提交说明清理 — 把本地运维事件从 git 历史里摘出去

## 1. 已拍板决策与显式边界不变量

- **[D1] 范围**：`upstream/v2..v2` 共 47 条提交，其中 7 条 Merge、3 条 Revert。
  - Merge 说明由 GitHub 自动生成（`Merge pull request #N from ...`），本身不含本地事件，**原样保留**——改写会让 PR 记录指向不存在的 commit。
  - Revert 说明必须引用被撤销的 commit，**原样保留**（`This reverts commit <sha>.`）。
  - 其余 37 条普通提交逐条审，**13 条带痕迹需改写，24 条本来就干净，原样保留**。
- **[D2] 改写标准——只讲功能**。保留：改了什么、为什么改（技术现象）、边界与已知遗留。删除以下五类：
  1. 日期时间（`2026-11-08`、`01:04`、`26 小时`）
  2. 环境标识（`线上`、`生产`、`本机`、本地反代版本号、上游中转域名、服务器名、容器名）
  3. 人名与内部流程（决策人姓名、拍板、多轮盲审与复核、内部工单）
  4. 验证计数（`123/123 测试通过`、`checkSyntax(346)`、`pathLeak(475)`、`90/90`）
  5. rebase 残留（`# Conflicts:` 块）
- **[D3] 技术论证保留**。像「20 轮裁 20 次」「长期模拟切割 < 30 次」「稳定前缀从几十 token 提到上千」这类描述问题严重性的说法保留——它们说明的是代码行为，不是本地环境。只把带具体环境/日期的表述改成中性说法。
- **[D4] 改写提交对象时不动文件内容**。t1 这一步只换 message，不碰 tree；改完后 `git diff v2 <新分支>` 必须为空。文档内容清理按 D5 单独提交，不走这一步、也不计入这条验收。
- **[D5] `.scratch/group-context-in-system/spec.md` 的内容单独处理**：把决策人、具体日期与实测统计改成中性技术描述，作为独立 commit 提交。
- **[D6] 执行必须在临时分支验证后再动 v2**，禁止直接改写当前分支。
