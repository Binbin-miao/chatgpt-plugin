# t2 — 纯函数单测

**独占文件写锁**：`test/groupContextSnapshot.test.mjs`（新建）

**依赖**：t1 完成（需 `rebuildThreshold` / `countNewerMessages` 已导出）

## 用例

`rebuildThreshold`：

| 输入 | 期望 | 说明 |
|---|---|---|
| 60 | 20 | 拉满窗口 |
| 45 | 15 | 拉满 3/4 |
| 10 | 4 | 未拉满，`ceil(10/3)=4` |
| 9 | 3 | `ceil(9/3)=3` 恰好等于下限 |
| 0 | 3 | 空窗口不低于下限 |
| undefined | 3 | 容错 |

`countNewerMessages`：

| 场景 | 期望 |
|---|---|
| `lastId` 在窗口中间（索引 40，共 60 条） | 19 |
| `lastId` 是最后一条 | 0 |
| `lastId` 不在窗口里（已滑出） | 60 |
| `lastId` 为空 | 60 |
| `chats` 为空数组 | 0 |
| `message_id` 是数字、`lastId` 是字符串 | 按 `String()` 归一同等匹配 |

## 写法

参照 `test/sessionProvider.test.mjs`：`node:test` + `node:assert/strict`，`import { rebuildThreshold, countNewerMessages } from '../model/core.js'`。

**注意**：`model/core.js` 会连带 import `Config`、`logger` 等 Yunzai 运行时依赖。若 import 失败，先确认仓库里现有测试是如何处理这类依赖的（`test/sessionProvider.test.mjs` 只 import 纯模块 `utils/sessionProvider.js`，可能不存在先例）。若确实无法 import，允许把两个纯函数移到 `utils/groupSnapshot.js` 再从 `core.js` re-export —— 此时 t1 需同步调整 import 路径。

## 验收命令

`package.json` 没有 `test` 脚本。新用例建议挂进 `test:chat`（`package.json` 的 `test:chat` 那一行追加 `test/groupContextSnapshot.test.mjs`），然后：

```bash
cd <仓库根目录>
npm run test:chat
```

若新增用例依赖 `model/core.js` 的运行时依赖导致无法 import，按 t2 备选方案把纯函数抽到 `utils/groupSnapshot.js`，并把新测试文件挂到 `node --test --test-force-exit` 直接跑。
