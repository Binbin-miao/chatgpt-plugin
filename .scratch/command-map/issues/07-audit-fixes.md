# 07: 审计发现的 6 处缺陷修掉，并用测试锁住

**What to build:** 2026-11-04 对 `v2` @ `4f273a1` 做了一次只读审计（4 份独立报告 + 真实地图 31 份 / 1396 条指令实测），确认 6 个会直接伤害用户的缺陷。这一票把它们修掉，每一项都要有回归测试锁住对应不变量——现有 112 条测试对这 6 项一条都没覆盖。

**Blocked by:** 05

**Status:** done

## 要修什么

1. **清理已卸载插件的地图挪到下载之后，并加骤减保护**
   `syncMaps` 原本在下载循环之前调用 `pruneUninstalled`。插件目录在 `git pull` / `pnpm` 改写期间会短暂扫不到，该插件就被当成「已卸载」，缓存被 `rm -rf`；同一轮若网络不通，缓存净损失且无法恢复。实测：3 份缓存 + 清单只报 1 个 → 另 2 份被删，返回值仍是 `ok:true`。
   验收：下载全失败时已缓存的地图一份都不能少；本次清单不足上一次的 70% 时不执行清理。

2. **别名歧义时先看主写法精确命中**
   `resolveCommand` 第 3 步（别名精确）遇到多条候选直接判 `ambiguous`，而第 5 步（关键词）有 `exactBare` 兜底。真实数据下，去掉 `#` 的写法有 30.9%（无参）/ 60.7%（带参）被误判歧义，`芙宁娜` 这种「主写法本身就等于输入」的也被拒。
   验收：歧义候选里若有且仅有一条主写法（去 `#`、忽略大小写）等于输入，直接采用该条。

3. **`risk:a` 设白名单闸门**
   原口径「risk 只记日志、不挡执行」的前提被推翻：351 条 `risk:a` 里有 18 条 `permission` 写着「实际无校验（任何群成员可执行）」，59 条为空。这两类框架没有可校验的权限位。
   验收：`risk:a` 且 `permission` 不含 master/主人/管理员/admin/本人 时，工具直接拒绝且不派发；`permission: master` 的高危指令仍可代执行。取舍见 `docs/adr/0015-command-map-risk-gate.md`。

4. **`guardAccept` 改引用计数，并发不互拆**
   原实现每次调用都 patch 一遍 `prototype.accept`，还原是栈序而非配对。两路并发时，先收尾的一路会把后一路的守卫拆掉，`#点赞` 又会被 genshin 改写成 `#角色详情`；两路都收尾后原型上残留匿名包装。
   验收：任一路收尾不得破坏另一路守卫；全部收尾后 `proto.accept` 等于原始函数。

5. **`countReplies` 去掉共享 `busy`**
   `busy` 是闭包级布尔，把插件并发发送误判成嵌套：`Promise.all` 发两条只计 1；首条失败次条成功时计 0，工具据此告诉模型「插件没回话」，而消息实际已经发出。
   验收：并发两条至少计到 1；首条失败次条成功仍计到 ≥1。

6. **非 `#` 指令代执行时短接 chat 插件**
   全库 156 条（11.2%）指令不以 `#` 开头（`*更新图像`、`打卡` 等）。`prepareMessage` 刻意保留 at 段，于是 `chatgpt` 规则也会命中，再跑一整轮 AI；该轮回复被计为「插件回话」，工具误报成功。
   验收：带 `__commandMapNested` 的事件进入 `chatgpt` / `chatgpt_for_firstperson_call` 时立即 `return false`。

顺带修两处零风险 P2：`readIndex` 的 `base` 改用 `new URL('.', url).href`（索引地址带 query 时原本全部下载失败）；`isPlaceholderCommand` 补判 `[话题]`、`[]`、`{}`。
