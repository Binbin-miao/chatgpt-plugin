# hermes-agent hook 机制

总评：双轨制 hook 系统——Python 插件（manifest + `register(ctx)` 注册回调）与 shell 脚本 hook（config.yaml 声明、allowlist 批准、stdin/stdout JSON 协议）共用同一 `invoke_hook` 分发，`pre_llm_call` 上下文只注入 user message 的 API wire 副本（api_content sidecar），系统提示词字节稳定以保 prompt cache。

- Hook 类型全集（`hermes_cli/plugins.py:109-204`）：40+ 事件，含 pre/post_tool_call、pre/post_llm_call、pre/post_api_request、api_request_error、pre/post_auxiliary_call、pre_verify、transform_llm_output、transform_terminal_output、transform_tool_result、transform_api_error_classification、流式观察（on_stream_start/delta/end、on_interim_message）、会话生命周期（on_session_start/end/finalize/reset/delete）、subagent_start/stop、网关类（pre_gateway_dispatch、post_gateway_admission、pre_command、gateway_platform_event、agent_loop_stopped）、审批观察、pre_transcription、post_compaction、kanban 系列等。
- 发现与注册：插件目录含 plugin.yaml/json manifest，`__init__.py` 暴露 `register(ctx)`；扫描顺序 bundled 仓库 plugins/ → `~/.hermes/plugins` → 项目 `.hermes/plugins`（需 `HERMES_ENABLE_PROJECT_PLUGINS=1`），目录内按名称排序（`hermes_cli/plugins_discovery.py:152,206-219`）；同名 project>user>bundled 覆盖；另有 entry_points 组 `hermes_agent.plugins`（:29）。回调经 `ctx.register_hook`（`hermes_cli/plugins.py:8`）。shell hook 在 config.yaml `hooks:` 段声明（`hermes_cli/config_defaults.py:1725`），须 allowlist 批准且检测脚本 mtime 漂移（`hermes_cli/hooks.py:269-345`）。
- pre_llm_call 入参（`agent/turn_context.py:862-874`）：session_id、task_id、turn_id、user_message、conversation_history、is_first_turn、model、platform、parent_session_id、sender_id。
- 返回值协议（`agent/turn_context.py:886-897`）：`{"action":"block","message":...}` 否决整回合（零模型调用，`turn_exit_reason=blocked_by_plugin_pre_llm_call`，`agent/turn_context.py:808`，首个 block 生效 :1241）；`{"context": str}` 或非空裸 str 注入；None 跳过。
- 注入位置实现：不进 system prompt；拼接结果只落在 wire 副本——`compose_user_api_content` 生成 `content + "\n\n" + injection`（`agent/turn_context.py:124-135`），stamp 到 live 消息的 `api_content` sidecar（:997-1041），发请求时 `substitute_api_content` 弹入 content（:138-144），live messages 不动故前缀字节稳定；多模态 list content 改为追加一个持久化 `{"type":"text"}` part（:1044-1073）。注入 user message 而非 system 正是为复用缓存前缀。
- 截断写盘：单 hook 上下文超 10000 字符（`tools/hook_output_spill.py:24` DEFAULT_MAX_CHARS=10_000，可配 hooks.output_spill.max_chars）写 `<HERMES_HOME>/hook_outputs/<session>/<uuid>.txt`（私有权限、独占创建，:53-99），注入头 500 + 尾 500 预览（:25-26,105-113）；I/O 失败仍返回无路径预览。线索属实，与源码一致。
- 多 hook 拼接：`"\n\n".join(_ctx_parts)`（`agent/turn_context.py:907`），顺序即插件发现顺序（目录名字母序）。
- 超时与异常：Python 回调受 `plugins.hook_callback_timeout`（默认 30s，上限 600，`hermes_cli/plugins_dispatch.py:183-184`）；超时 worker 被放弃不 join，60s 抑制窗口、最多 3 个弃 worker（:64-66）；pre_tool_call fail-closed，pre_llm_call 等 fail-open（`hermes_cli/plugins.py:1800-1806`）；收集层整体 try/except 失败返回空串（`agent/turn_context.py:908-910`）。shell hook 默认 timeout=60s、上限 300（`agent/shell_hooks.py:37-38`），超时 kill 整个进程组（:494-531）；pre_llm_call 的 stdout 支持 block 与 context 双方言（:675-681）。
- HTTP 插件线索核实：「timeout=3、异常 return None」是文档示例代码而非内置插件——hooks.md 的 memory recall 示例用 httpx.post(timeout=3)、except return None（`website/docs/user-guide/features/hooks.md:736-752`）；内置插件请求超时多为 30s（如 `plugins/browser/_common.py:92`）。
- agent 侧主动工具钩子：无 post_response 类事件；插件主动能力走 PluginContext——`ctx.register_tool` 注册工具、`inject_message` 主动向会话注入消息（`hermes_cli/plugins_injection.py:12-70`）、`ctx.side_question` 反问 agent 自身 LLM。post_llm_call 仅观察，返回值忽略。
- 意外点 1：oversized spill 机制注明移植自 openai/codex PR #21069（`agent/turn_context.py:877`）。
- 意外点 2：被 block 否决的 prompt 持久化为占位符 `[Message withheld: a pre_llm_call policy hook blocked it.]`，后续回放、压缩、记忆检索只见占位符，原文仅存 display metadata（`agent/message_metadata.py:76-81`）。
- 意外点 3：safe worker 模式下整个 hook 分发被短路——`invoke_hook`/`has_hook` 直接返回空（`hermes_cli/lifecycle.py:30-37`）。
