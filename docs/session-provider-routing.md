# 会话分流（按群 / 私聊指定模型提供商）

同一台 Bot 可以让不同群、不同私聊走不同的模型提供商，甚至不同模型：二次元群走便宜快的线路，
技术群走贵的强模型，出问题的群单独换一条，互不影响。对照物是 AstrBot 的「自定义规则」，
多一项能力：**规则里可以直接写模型名**，不必为了换模型另建一条提供商。

## 配置位置

锅巴 → 「会话分流」分组（在「对话」之后、「语音」之前）。

- `enableSessionProviderRule`：总开关，默认关闭。关闭时全部走「对话 通用设置」里的默认提供商。
- 规则共 5 个槽位，一个槽位四格：提供商 / 模型名称 / 生效群聊 / 生效私聊账号。
  **第一个命中的规则生效**（数组顺序即优先级，槽位在面板上从上到下排列）。
- 「模型提供商」选「不启用」即停用该槽位；没有单独的 `enabled` 字段。
- 选群用多选框，`生效私聊账号` 填 QQ 号即可（其他适配器填完整 id），多个用逗号分隔。

手改 `config.json` 时 `sessionProviderRules` 的形态：

```json
[
  {
    "id": "r_8f2a1c3d",
    "providerId": "56e3dfa4-8f31-4213-95dd-04fc12b3e03d",
    "model": "",
    "groups": ["1055241628", "892283141"],
    "privateUsers": ["3589629156"]
  }
]
```

`providerId` 为空即停用；`model` 为空即沿用提供商自带的模型。**数组不定长**：面板只显示前 5 条，
第 6 条起靠手改配置文件，仍然生效，且面板保存时原样保留（不会因为面板只认识 5 条就被抹掉）。

## 运行时行为

入口在 `apps/chat.js` 的 `abstractChat()`，逻辑与索引在 `utils/sessionProvider.js`：

- 总开关关闭、未命中、或规则里的提供商已被删除 → 一律回落全局默认，**只降级不阻断**。
  规则引用的提供商失效时同一原因只 warn 一次，不会每条消息刷一行日志。
- 命中规则且规则里写了 `model` → 覆盖该提供商的模型字段（`MODEL_FIELDS[type]`），不改配置本身。
  覆盖会回写进本次请求的配置快照，`Core.sendMessage` 重新解析提供商时拿到的仍是覆盖后的模型。
- 会话管理（`#结束对话`、`#清除最近N条`、`#对话列表`）与对话请求用同一套判定算 key，
  分流群里删的、清的就是它自己那份会话。
- 回退：`model/core.js` 要求备用与主条目同协议且不是同一条目，否则整轮抛错。规则把某个群指到
  另一种协议的提供商时，本次对话**自动不启用回退**，而不是让那个群每次都失败。

## 怎么确认生效

规则、提供商与模型名在面板「会话分流」分组里直接可见，没有再额外提供查询指令。
运行期只看日志：`Config.debug` 打开时命中分流会打一行 `[chatgpt] 会话分流命中规则 N`。

## 已知限制

- **填了 `model` 会让该会话历史从零开始**：模型名参与会话隔离（`connectionVersion`），换模型等于换
  一段对话，历史不会接上。这不是 bug，面板字段说明里也写了。
- 规则**不影响群聊自主回复的判断模型**（`groupReply.provider` 是独立配置），也不影响记忆召回、
  图片识别等子调用；它只改正式对话使用的那条线路。
- 不支持通配符，所有规则都是精确匹配；通配会带来「精确 vs 通配谁优先」的复杂度，而全局默认已经
  覆盖了"给所有群设一条"的场景。
- 不支持按用户分流（同群内不同人不同模型）：会让同一段对话的模型来回跳，破坏缓存。
- 机器人换群后群号不会自动同步，需要手动改规则。
