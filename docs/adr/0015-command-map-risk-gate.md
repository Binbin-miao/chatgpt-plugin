# 代执行对管理/破坏性指令设白名单闸门

状态：已采纳（2026-11-04）。需求与决策过程见 `.scratch/command-map/spec.md`。

指令地图的每条指令都带一个风险档（`q` 只读 / `w` 有副作用 / `a` 管理或破坏性）。最初的口径是「`risk` 只用于日志与模型判断，不挡执行」——理由是权限应该由框架的 `permission` 位与插件自己的校验决定，工具层再拦一遍容易出现「插件本来能用、却被地图数据按住」。

2026-11-04 的审计推翻了这个前提：真实地图里 351 条 `risk:a`，其中 18 条的 `permission` 直接写着「实际无校验（任何群成员可执行）」（集中在 `ZZZ-Plugin` 的 `#zzz删除全部资源`、`#zzz重置深渊排名`、`#zzz设置检查更新时间…` 等），另有 59 条 `permission` 为空。对这两类，框架没有任何可校验的权限位——「交给框架」等于没有闸门，任何群成员说一句「帮我重置一下深渊排名」就能借 AI 删掉本群全部排名数据。

于是改为：`risk:a` 且 `permission` 不含「master / 主人 / 管理员 / admin / 本人」时，工具层直接拒绝代执行，回执明确告诉模型「这条是管理或破坏性操作，请你自己发送」，不派发、不试探。

## 考虑过的替代方案

- **维持原口径，只记日志**：18 条「任何群成员可执行」的删数据指令会被 AI 无障碍触发。这不是理论风险：地图数据自己都写明了没有校验。
- **`risk:a` 一律拒绝代执行**：最安全，但 233 条 `permission: master` 的常用管理指令（如 `#图鉴升级`）也一并失去代劳能力，等于把「帮我升级图鉴」打回「你自己发」。代执行对主人的核心价值被砍掉一大块。
- **只拒 `permission` 为空的条目**：漏掉「实际无校验（任何群成员可执行）」「默认 master」这类自由文本表述，正是最危险的那 18 条。
- **让地图仓把 `permission` 规范成枚举**：方向正确，但要改数据契约与全部 31 份地图，且存量地图不会一夜之间升级；工具层闸门可以立刻生效，不依赖数据先行。

## 已知约束

- `permission` 是自由文本，白名单靠关键词匹配。地图作者写出白名单之外的表述（如「仅限群主」）时会被误拒——误拒的方向是安全的，用户仍可自己发。
- 反过来，地图若把一条实际无校验的指令错标成 `master`，会被误放行。放行后框架仍会按规则的 `permission` 再判一次，但这层在「插件自己没写 permission」时是空的。**地图数据的准确性仍是最终边界**，白名单只能挡住已知的坏标注。
- 闸门只作用于 `risk:a`。`w`（有副作用）不拦——发消息、点赞、签到都属于这一类，拦了代执行就没意义了。
- 放行的 `risk:a` 会在日志里带上 `permission` 原文，便于事后核对「为什么这条被放过了」。
